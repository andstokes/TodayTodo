# 今日清单（TodayChecklist）

一个完全本地运行的 Windows 每日待办小程序。默认使用普通窗口层级：它不会置顶在其他应用窗口上；还可手动启用实验性的“桌面模式”，把窗口连接到 Windows 桌面背景层。

应用使用原创的蓝色“日历＋勾选”图标，并为可执行文件、窗口和系统托盘提供适合不同显示尺寸的图标资源。

## 下载与快速开始

当前版本为 **0.6.1 预发布候选版**，面向 Windows 11 x64（Intel/AMD 64 位）。已通过本机 Release 零警告构建、61 项应用测试、26 项发布脚本检查及隔离启动检查；干净 Windows 11 环境的手工验收尚未完成。

1. 打开 [v0.6.1 下载页](https://github.com/andstokes/TodayTodo/releases/tag/v0.6.1)，下载 `TodayChecklist-0.6.1-win-x64.zip`。`Source code` 是源码，不是可直接运行的软件。
2. 将 ZIP **完整解压**到本地文件夹，打开其中的 `TodayChecklist` 文件夹。
3. 双击 `TodayChecklist.exe`；无需安装 .NET、Visual Studio，也不需要管理员权限。不要只复制 EXE，其他运行文件必须保留。
4. 点击底部“＋”添加任务；隐藏后可通过系统托盘重新打开，完全退出需使用托盘菜单的“退出”。

完整的 [免安装版使用说明](docs/PORTABLE.txt) 包含升级、备份、数据位置和移除方法，也随 ZIP 提供。更新旧版前请先导出备份，并从托盘退出旧版。

如果 Windows 显示来源或信誉警告，请先核对下载仓库及 ZIP 哈希，不要关闭系统安全防护。可在 PowerShell 中用 `Get-FileHash '压缩包完整路径' -Algorithm SHA256`，与下载页的同名 `.sha256` 文件比较。

## 常用操作

| 操作 | 使用方式 |
| --- | --- |
| 新增任务 | 点击底部“＋”，填写标题；可展开备注与重复规则 |
| 保存或取消新增 | 标题中 Enter 保存、Esc 取消；备注中 Ctrl+Enter 保存 |
| 修改、删除 | 双击任务编辑；右键菜单删除，删除后可撤销 |
| 调整顺序 | 按住未完成任务卡片上下拖动；完成项自动沉底、淡化 |
| 查看历史 | 点击日期旁的历史图标，按日期滚动查看过往完成事项 |
| 时段分隔 | 底部分隔线图标或 Ctrl+Shift+D；蓝色勾号为开、灰色斜线为关 |
| 更换数据盘 | 齿轮设置 → 数据保存位置；选择父文件夹，迁移后按提示重开 |

“上午／下午／晚上”居中显示为蓝色半粗体；可以拖动分隔线调整边界，也可拖动任务跨时段。默认的标准窗口模式不会盖住其他应用窗口；实验性桌面模式可在设置中按需启用。

## 当前功能

- 点击底部“＋”以行内方式添加标题、备注和重复规则，完成项自动排在未完成项下方。
- 支持每天、工作日、每周、每月重复；同一规则不会生成多个未完成实例。
- 未完成任务跨日自动顺延，并保留原始日期和累计顺延天数。
- 设置中心可隐藏“已顺延 N 天”，不影响跨日顺延和已有记录。
- 可选上午／下午／晚上分隔线，默认关闭；标题居中显示为蓝色半粗体，点击底部分隔线图标或按 Ctrl+Shift+D 切换。蓝色勾号表示开启，灰色斜线表示关闭。
- 拖动分隔线调整时段边界，三条线始终保持上午、下午、晚上顺序；任务可跨线拖动，已完成项单独置底。切换显示不改变任务排列，重启后保留设置及安排。
- 点击日期旁的历史图标，可按日期向下滚动查看过往每天的已完成事项；当天完成项会在日期更新后进入历史记录。
- 双击编辑、右键删除、撤销删除；按住未完成任务卡片即可拖拽排序。
- 已完成任务会自动沉底，并以灰化背景和降低不透明度弱化显示，但仍可辨认和取消勾选。
- 关闭到系统托盘、单实例运行、手动导入/导出 JSON 备份。
- 可选开机启动，默认关闭；只创建当前用户 Startup 文件夹快捷方式。
- 可把任务、备份、设置和日志安全迁移到其他本地磁盘或移动磁盘。
- 标准模式默认启用；实验性桌面模式失败时自动回退。

## 安全边界

程序以普通用户权限运行，不请求管理员权限，不修改注册表，不创建计划任务，不联网，不发送遥测，也不包含自动更新器。任务正文不会写入日志。

数据默认位于：

```text
%LocalAppData%\TodayChecklist\
├─ data\tasks.json
├─ data\tasks.last-good.json
├─ backups\
├─ logs\
├─ .todaychecklist-store.json
└─ settings.json
```

选择自定义路径后，上述正文数据会全部迁移到“所选父文件夹\TodayChecklist”。默认位置只保留 location.json 和 location.last-good.json，内容仅为路径、架构版本和随机存储 ID，不含任务或备注。

保存时先写临时文件、重新读取并验证，再原子替换正式文件。程序保留 last-good 副本和最近 14 个每日备份。主文件与 last-good 都无法验证时，只读打开且不覆盖原文件。

历史记录直接来自同一份 tasks.json 中保留原日期的已完成任务，并不是另一套不可变档案；导入或恢复备份会同时恢复当时的今日任务和历史记录。程序关闭时不会在后台运行，日期切换会在下次启动时安全补做。

更完整的说明见 [安全设计](docs/SECURITY.md) 与 [手工验收清单](docs/ACCEPTANCE.md)。

## 开发环境

- Windows 11 x64（首版发布验收范围；代码目标框架保持不变）
- .NET 10 SDK 10.0.400 或兼容补丁版本
- Visual Studio 2026 Community（可选，需“使用 .NET 的桌面开发”工作负载）

运行测试：

```powershell
$env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'
dotnet test --project .\tests\TodayChecklist.Tests\TodayChecklist.Tests.csproj -c Release --no-restore
```

生成 ZIP 自包含便携版（使用已有 SDK 与依赖缓存，不自动下载）：

```powershell
.\scripts\publish.ps1
```

发布脚本先检查缓存，执行 Release 构建、全部应用测试和发布脚本回归测试，再从独立的干净目录发布。它会将 ZIP 解压到含中文和空格的路径，逐文件核对路径、大小和 SHA-256，并运行解压后的 EXE 做隔离 WPF 启动检查。

当前版本的输出目录是 `artifacts\releases\0.6.1`，其中包含：

- `TodayChecklist-0.6.1-win-x64.zip`：多文件、自包含便携包。
- ZIP 同名的 `.sha256` 文件：供传输后核对。
- `files.sha256.json`：ZIP 内应用文件的完整清单。
- `acceptance.json` 和 `验收记录.md`：自动检查结果，以及待完成的干净 Windows 11 x64 手工验收。

版本号从项目配置读取；已有同版本目录时立即停止，不覆盖原包。工作目录及失败现场保留在 `artifacts\release-work`。缺少 SDK、依赖清单、缓存包或许可元数据时停止，不自动安装。首次准备或更新依赖必须另行批准。

ZIP 只包含一个 TodayChecklist 文件夹；完整解压后双击 TodayChecklist.exe，无需预装 .NET。用户说明见 [免安装版使用说明](docs/PORTABLE.txt)，程序内已有的真实数据目录不能放进分发包。

本机自动检查通过只代表候选包可供验收。必须在干净 Windows 11 x64 环境完成 [手工验收](docs/ACCEPTANCE.md)，并关联 ZIP 哈希记录结果后，才能标记为可发布。

## 隔离测试模式

对解压后的程序进行自动启动检查：

```powershell
.\scripts\smoke-test.ps1 -ExecutablePath '解压后 TodayChecklist.exe 的完整路径'
```

每次自动检查在 `artifacts\smoke-tests\run-随机ID` 中建立独立临时目录，设置子进程的 TEMP/TMP，并使用另一个工作目录启动。只检查该次产生的会话，不选择全局“最新目录”，也不修改父进程的环境变量。默认超时为 30 秒；超时只结束该次启动且目标匹配的进程。

不传 `-ExecutablePath` 时仍检查旧位置 `artifacts\publish\win-x64\TodayChecklist.exe`，仅用于兼容原有调用；它不代表最新 ZIP 内容。

手动查看隔离界面，可给解压后的 EXE 传入 `--test-mode`。手动模式继续使用调用方的 `%TEMP%\TodayChecklist-Test\session-随机ID`；自动发布检查会把 TEMP/TMP 定向到项目内。

测试模式创建虚构任务并显示绿色隔离提示，使用独立单实例标识，禁止开机启动、桌面层连接、数据迁移和正式导入导出，不会读取正式清单。

只验证发布脚本逻辑，不生成发布包：

```powershell
.\scripts\test-release.ps1
```

## 第一次运行建议

1. 先使用 --test-mode 检查界面、底部加号、双击编辑、右键删除、拖动和历史记录。
2. 确认绿色隔离提示中的路径位于 %TEMP%\TodayChecklist-Test，设置中的桌面模式、开机启动和数据迁移不可用。
3. 再正常启动正式版，保持“标准模式”和“开机启动关闭”。
4. 添加一条无隐私内容的任务，退出并重新打开，确认数据保存。
5. 导出一次备份并确认 JSON 文件存在。
6. 确认普通应用窗口会遮住清单窗口。
7. 若要更换数据磁盘，先选择一个无重要同名子目录的父文件夹；迁移完成后按提示重新打开。
8. 需要时再尝试桌面模式；Explorer 更新后若失效，切回标准模式即可。

发布脚本不会自动安装软件、下载依赖或写入系统目录。现有微软测试运行器只参与开发验证，不随应用分发。
