# 安全设计与风险边界

## 权限和外部影响

- 清单程序的清单文件明确使用 `asInvoker`，不会触发 UAC 提权。
- 运行期没有网络客户端、遥测、广告、自动更新或远程内容。
- 不修改注册表，不结束、重启、注入或修改 Explorer 进程。
- 默认写当前用户的 `%LocalAppData%\TodayChecklist`；用户选择自定义位置后，任务、备份、设置和日志都迁往该位置，默认目录仅保留不含任务正文的路径指针。用户明确开启开机启动时，额外写入当前用户 Startup 文件夹中的 `TodayChecklist.lnk`。
- 关闭开机启动时，仅当快捷方式的目标精确等于当前可执行文件时才删除它，避免误删用户的其他快捷方式。

## 数据完整性

正式 JSON 数据具有固定架构版本和字段约束。每次保存经过以下流程：

1. 在内存中验证文档。
2. 在相同目录创建随机命名的临时文件。
3. 写入并刷新到磁盘。
4. 重新读取临时文件并再次验证。
5. 使用文件系统原子替换正式文件，同时保留 last-good。
6. 轮换每日备份，仅保留最近 14 份。

界面修改在保存前保留内存快照；保存失败会恢复快照。导入文件在替换前必须完整反序列化并通过验证，同时先保存导入前备份。

## 数据位置迁移

- 自定义位置只支持本地固定磁盘和移动磁盘，首版拒绝网络共享、系统目录、符号链接和被其他文件占用的非空目标目录。
- 每个数据根目录都有随机存储 ID；复制、激活和旧目录清理前都必须核对所有权标记。
- 数据先复制到目标磁盘的随机暂存目录，并逐文件比较长度和 SHA-256；任务、设置及 last-good 必须重新读取验证。
- 只有验证完成后才原子更新 `%LocalAppData%\TodayChecklist\location.json`，其 last-good 同时更新为新位置。
- 路径切换后只清理经过存储 ID 验证的已知目录和文件，不删除未知内容。清理失败会保留新位置并报告旧路径。
- 自定义移动磁盘缺失或路径指针损坏时，程序不会创建空清单或静默回退到 C 盘。

## 隐私

日志只记录时间、固定事件代码和异常类型，不记录任务标题、备注或 JSON 正文。日志默认保留 7 天。

任务没有加密。任何能够登录该 Windows 账户并读取 LocalAppData 的人都可能读取任务内容。因此不建议写入密码、恢复码、身份证号、银行卡信息或高度敏感的工作资料。

## 隔离测试模式

- 只有显式传入 --test-mode 才会启用；生产模式的路径和行为保持不变。
- 每次测试使用 %TEMP%\TodayChecklist-Test\session-随机ID 下的新目录，并使用独立的互斥锁和命名管道。正式模式继续沿用旧版本的单实例标识，防止升级期间新旧版本并发写入；测试启动流程不会读取 %LocalAppData%\TodayChecklist\location.json。
- 测试数据全部是程序生成的虚构内容，主窗口持续显示测试目录，托盘名称也明确标注为隔离测试。
- 测试模式使用无系统副作用的开机启动和桌面层服务；设置界面同时禁用开机启动、桌面模式和数据位置迁移，托盘不提供正式导入导出。
- --smoke-test 不能单独使用；它必须依附于测试模式，完成主窗口和历史窗口的真实 WPF 加载、布局及隔离持久化检查后自动退出。

## 历史记录边界

历史记录不是单独的不可变数据库，而是从 tasks.json 中按任务原日期读取已完成项目。因此导入、恢复或整体替换任务数据会同时影响历史记录。程序关闭期间不会执行后台任务；跨日处理会在下次启动时补做。当前历史记录没有自动清理期限，长期使用时数据文件会随完成项目数量增长。

## 桌面模式

桌面模式使用有边界的 Win32 Shell 窗口查找与 `SetParent`，把程序窗口放入 Explorer 的 WorkerW 背景层。WorkerW 不是微软承诺稳定的公开 API，Windows 或 Explorer 更新可能让它失效。因此：

- 该模式默认关闭，并在设置中明确标为实验性。
- 查找操作有固定超时和有限次数重试。
- 不创建远程线程、不读写 Explorer 内存、不发送关闭或重启命令。
- 连接失败会退回标准模式并保存回退结果。

## 卸载与恢复

程序是便携版，不注册系统组件。卸载前先在设置中关闭开机启动并退出，然后删除发布目录。任务数据不会随程序目录自动删除；确认不再需要备份后，可手动删除 `%LocalAppData%\TodayChecklist`。

如果数据异常，先复制当前设置中显示的整个数据目录，再尝试导入 `backups` 中的备份。不要在没有副本时直接编辑或覆盖 `tasks.json` 或 `location.json`。

## 离线发布边界

发布脚本不执行依赖还原：检查已有 SDK、project.assets.json、缓存包及文件，随后使用 --no-restore 构建和发布。测试先构建，再以 --no-build 执行；禁止零测试或跳过测试作为通过结果。构建和测试遥测关闭，依赖源限制为空的本地目录。

发布与自动启动检查的临时目录、CLI 专用目录和虚构数据均在项目 artifacts 内。自动启动只使用 --test-mode --smoke-test，独立 TEMP/TMP、工作目录和会话；超时仅结束原始进程对象对应且已验证可执行目标的测试进程。

打包源仅为新生成的发布目录，拒绝数据、备份、日志、测试依赖和源码。包内依赖许可证、第三方声明及原包仅提供的许可链接元数据按实际 deps 清单收集，不下载新内容。ZIP 解压后逐文件核对路径、大小和 SHA-256，并检查运行前后应用目录不变。

产物先在随机工作目录创建并验证，通过后在同卷原子移动整个候选目录。已有同版本目录时拒绝覆盖；失败现场和旧发布包保留。自动记录始终标记候选包，干净系统的人工验收结果另外保存并关联 ZIP 哈希。
